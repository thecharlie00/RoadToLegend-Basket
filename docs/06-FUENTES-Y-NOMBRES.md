## 5. Pipeline de datos

`investigación opcional → raw versionado → validación/licencia → alteración determinista → paquete de juego → pruebas → publicación`.

- `raw/` nunca se empaqueta por defecto.
- Cada persona generada tiene nacionalidad, nombre/apellido de pools, edad, físico, posición, arquetipo, atributos, potencial oculto y contrato.
- Alteración de nombres realistas: versión, semilla, reglas por nacionalidad y lista de exclusiones; no deformar nombres reales de forma ofensiva.
- Instrucción fase 3: solo se generan/alteran nombres de jugadores. Los nombres de equipos, clubes y competiciones permanecen como datos del paquete y no se renombran desde el motor.
- Instrucción fase 4: los nombres de jugador deben ser versiones modificadas de jugadores conocidos para mantener realismo. Paquete jugable `data/players/inspired-names.json` con 77 nombres alterados; auditoría interna `research/player-name-inspirations.json` con `referenceName` y `notForDistribution: true`, nunca empaquetada. Estado legal `pending-clearance`; no implica afiliación ni licencia.
- Ratings de investigación no se copian como verdad: se transforman a modelo propio y se documenta metodología.
- Separar datos masculinos/femeninos y épocas; no compartir salarios ni reglas por defecto.
- Eventos/logros/cosméticos con IDs estables; texto localizado, condiciones y efectos declarativos.
